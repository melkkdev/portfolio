# 포트폴리오 사이트 리디자인 브리프

> 작성일 2026-11-16 · 대상: https://melkk-dev.web.app (Flutter Web + Firebase)

## 1. 사이트 개요
- **목적**: Flutter 앱 개발자(경력 3년 6개월) 이력서를 대신하는 원페이지 포트폴리오. 채용 담당자와 면접관이 주로 봅니다.
- **구조**: 한 페이지를 세로로 스크롤하며, 최대 폭 860px로 가운데 정렬합니다.
- **데이터**: 모든 내용은 Firestore에서 불러오고, 관리자 모드에서 바로 고칠 수 있습니다.

## 2. 주요 기능 (리디자인 후에도 유지)

### 방문자
| 영역 | 내용 |
|---|---|
| Hero | 직무(모노 폰트 eyebrow), 이름, 한 줄 소개, 경력 연차, GitHub 링크, **PDF 다운로드** 버튼, 오른쪽에 기울어진 폰 목업 3개 |
| 01 소개 | 자기소개 본문. 굵게·강조 같은 마크업 텍스트를 지원합니다 |
| 02 기술 스택 | 그룹별 스킬 칩(언어/프레임워크/상태관리/백엔드 등) |
| 03 경력 | 회사 카드: 회사명, 기간, 역할, 주요 업무 목록 |
| 04 프로젝트 | 프로젝트 카드: eyebrow, 제목, 요약, 정보 행(소속/기간/플랫폼/주요 기능/기술 스택/GitHub), 수치 강조(stat). 스크린샷 갤러리는 세로형이면 폰 갤러리, 가로형이면 데스크톱 갤러리로 보여 줍니다 |
| 이미지 뷰어 | 스크린샷을 누르면 전체 화면으로 크게 보고 넘길 수 있습니다 |
| PDF 내보내기 | 포트폴리오 전체를 PDF로 만들어 미리 보고 내려받습니다 |

### 관리자
- 로그인 다이얼로그를 열고, 로그인하면 상단에 관리자 배너가 뜹니다.
- 섹션마다 편집 다이얼로그를 씁니다(프로필, 소개, 스킬, 경력, 프로젝트).
- 프로젝트를 추가하고 삭제할 수 있고, 오른쪽 패널에서 **드래그해 순서를 바꿉니다**.
- CLI 업로드 도구(`tools/portfolio-upload`)로 앱 프로젝트를 자동 등록합니다.

## 3. 현재 디자인의 느낌
- **톤**: 차분하고 정돈된 "개발자 문서" 느낌. 깔끔하지만 개성은 약합니다.
- **컬러**: 연회색 배경 `#EEF0EE`, 흰 카드, 딥 그린 포인트 `#006E51`, 연녹 `#E2EFE9`.
- **타이포**: Noto Sans KR(본문), JetBrains Mono(eyebrow, 섹션 번호). 이름과 태그라인은 800 굵기입니다.
- **장식**: 섹션 번호(01~04), 라운드 16 카드, 얇은 라인. 움직임은 거의 없습니다.
- **아쉬운 점**
  - 카드가 모두 같은 무게라서 대표 프로젝트가 눈에 띄지 않습니다.
  - Coupley, 콕체크처럼 아기자기한 앱이 많은데, 사이트 톤이 그 분위기를 보여 주지 못합니다.
  - Hero에서 "이 사람이 어떤 개발자인지"를 보여 주는 시각 요소가 폰 목업밖에 없습니다.

## 4. 리디자인 방향 (제안)
- **키워드**: 따뜻함 · 아기자기 · 신뢰감. 귀엽되, 이력서로서의 가독성은 지킵니다.
- **컬러**: 크림/웜화이트 배경에 코랄·피치 포인트를 주고, 보조 색은 민트나 세이지로 둡니다. 녹색 계열을 유지하고 싶으면 세이지로 부드럽게 바꿉니다.
- **타이포**
  - 제목에 둥근 디스플레이 폰트를 씁니다(예: Jua, Gowun Dodum, Pretendard Bold 계열).
  - 본문은 Pretendard나 Noto Sans KR로 가독성을 챙깁니다.
- **형태**: 큰 라운드(20~28), 부드러운 그림자, 스티커나 칩 같은 태그, 손그림 느낌의 작은 아이콘이나 캐릭터 포인트.
- **레이아웃**
  - Hero: 자기소개와 함께 대표 앱 폰 목업을 크게 보여 주고, 핵심 수치 3개(경력 연차, 출시 앱 수 등)를 배지로 답니다.
  - 프로젝트: 대표 1~2개는 큰 피처 카드로, 나머지는 그리드 카드로 위계를 나눕니다.
  - 기술 스택: 그룹별로 컬러 칩을 쓰고 숙련도를 은은하게 구분합니다.
  - 경력: 세로 타임라인으로 바꿉니다.
- **모션**: 스크롤하면 섹션이 살짝 페이드업하고, 폰 목업이 은은하게 흔들리며, 카드에 호버하면 떠오릅니다. 과하지 않게 둡니다.
- **기타**: 상단 고정 미니 내비(소개·스킬·경력·프로젝트 앵커), 모바일 폭 대응을 점검하고, 같은 톤으로 PDF 스타일도 맞춥니다.

## 5. 지켜야 할 것
- Firestore 스키마(`ProjectModel` 등)와 관리자 편집 기능, CLI 업로드 도구는 그대로 둡니다.
- 레퍼런스는 분위기만 참고하고, 에셋은 복제하지 않습니다.
- 채용 담당자가 30초 안에 "누구인지, 무엇을 만들었는지"를 파악할 수 있어야 합니다.
